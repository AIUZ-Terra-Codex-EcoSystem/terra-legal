# Terra Naming Standard

**Repository:** `terra-legal`  
**Role:** normative naming donor surface  
**Creator:** Abdurashid Abdukarimov — ORCID 0009-0000-6394-4912

## Purpose

This standard governs names used for Terra, AIUZ, the Fractal Metascience Foundation, FMP, protocols, repositories, publications, interfaces, services, and public initiatives.

A name is semantic infrastructure. It must preserve origin, meaning, scope, and continuity across languages and repositories.

## Source-first rule

Before proposing a new name:

1. search the existing Terra and FMP corpus;
2. search prior names, aliases, archived drafts, and donor repositories;
3. reuse an established name when it already performs the required role;
4. create a new name only when no adequate name exists.

## Core rules

### Meaning before promotion

A name must explain a real role. It must not be chosen only because it sounds advanced, global, intelligent, sovereign, final, or revolutionary.

### One primary role

Every name has one declared primary role. Do not use one undefined name to imply that an object is simultaneously a legal entity, theory, product, protocol, repository, financial instrument, and institution.

### Traceable origin

Every accepted name records:

- source language;
- literal or historical meaning;
- cultural context;
- first known ecosystem use;
- operator decision;
- donor files consulted;
- accepted spelling and aliases.

### Language review

Every public name is checked at minimum in English, Russian, and Uzbek Latin. Additional language checks apply when another audience is targeted.

Review:

- pronunciation;
- unwanted meanings;
- misleading associations;
- religious and cultural sensitivity;
- transliteration stability;
- search ambiguity.

### Legal review boundary

A language review is not legal clearance. Commercial, institutional, or international use requires a separate record of domain, entity-name, and trademark review status. Do not claim legal clearance when only an informal search occurred.

### Long-term resilience

A name should not depend on a temporary platform, marketing trend, unsupported technical claim, political moment, vendor, or performance promise.

Long-term resilience is a reasoned assessment, not a prediction of permanent survival.

## Required checks

### NULLO

Does the name add necessary distinction, or only semantic noise?

### PLT

Can its origin, aliases, decision, and later changes be reconstructed?

### UCOMM

Can participants use the name without silently assigning incompatible meanings?

### EUO

Can it remain understandable across new repositories, languages, and contexts?

### FMP

Does it preserve its role across scales without pretending that one layer is the whole system?

### Detox

Does it rely on pressure, prestige borrowing, exaggerated novelty, commercial bait, or unsupported authority?

## Syntax

### Repository names

- lowercase Latin characters;
- hyphens between words;
- no spaces or emoji;
- no unexplained abbreviations;
- no silent renaming of established repositories.

Example: `terra-legal`.

### Protocol and standard filenames

Use uppercase descriptive filenames with underscores for stable donor documents.

Examples: `NAMING_STANDARD.md`, `TRACELOG_PROTOCOL.md`, `BRAND_IDENTITY_STANDARD.md`.

### Publications

Avoid unsupported title claims such as `complete`, `universal`, `final`, `proven`, or `world-first` unless the work establishes them.

### Acronyms

Expand on first use. Record exact expansion, pronunciation, language stability, and known collisions.

## Status values

- `proposed`;
- `under linguistic review`;
- `under legal review`;
- `accepted for internal use`;
- `accepted for public use`;
- `accepted with jurisdiction limits`;
- `deprecated`;
- `blocked`.

A name does not become approved merely because it appears in a draft or AI-generated file.

## Change and deprecation

A name change preserves the previous name, reason, aliases, affected surfaces, date, operator decision, and TraceLog record.

Deprecated names remain visible in provenance but are marked so they are not reused accidentally.

## Required companions

- `NAMING_CARD_TEMPLATE.md`;
- `naming/registry/README.md`;
- one registry card per accepted or deprecated public name;
- a `TRACELOG.md` entry for material naming decisions.

## Provenance

This standard is a detoxed bridge from the operator-supplied Terra and FMP naming materials, Rule 0, and NULLO–PLT–UCOMM–EUO–FMP checks. Earlier absolute formulations were converted into reviewable operational criteria without removing the source principle that names carry responsibility and continuity.

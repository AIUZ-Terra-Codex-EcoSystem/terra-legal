# Full Packaging Protocol

This file defines the Terra approach to full packaging of documentary, publication, repository, and release surfaces.

It is not a static export recipe.
It is a living packaging protocol that preserves trace, multilingual structure, documentary role, and publication readiness without flattening the ecosystem into one file dump.

## Purpose

Full packaging exists to make a work surface:

- readable by humans;
- traceable across repositories;
- portable across release channels;
- publication-ready where applicable;
- coherent with donor rules, directives, validation, and detox constraints.

## Source-first packaging rule

Before assembling any package:

1. read the relevant donor surfaces first;
2. identify what already exists in the corpus;
3. reuse or bridge existing material where possible;
4. only then assemble a new package surface.

## Packaging layers

### 1. Documentary layer

Must include the normative and explanatory files needed to understand the package:

- README;
- role note;
- living index or trace map;
- provenance note;
- donor references where extraction occurred.

### 2. Validation layer

Must include the minimal validation surfaces relevant to the package role:

- validation protocol;
- audit or review rule;
- citation and bibliography relation where scholarly claims are involved.

### 3. Publication layer

Where a package is publication-facing, it should expose:

- readable abstract or summary;
- citation metadata;
- bibliography subset or donor relation;
- explicit file-role mapping;
- language surfaces when multilingual packaging is required.

### 4. Release layer

Where a package is meant for repository release or archival distribution, it should preserve:

- release bundle identity;
- checksum or equivalent integrity signal;
- relation to repository root;
- traceable packaging date or event.

## Multilingual packaging protocol

Where multilingual packaging is required, the package should preserve:

- primary working language surface;
- secondary language surfaces where required by audience or ecosystem role;
- explicit note when a surface is machine-translated or bridge-only;
- meaning continuity across languages rather than word-for-word imitation.

## Packaging modes

### Light package

Use when a surface is meant for quick review or bridge distribution.

Should contain:

- essential documentary files;
- a minimal publication or repository entry path;
- no archive debris.

### Full package

Use when a surface is meant for deposit, publication, formal review, or long-term transfer.

Should contain:

- documentary layer;
- validation layer;
- publication layer where applicable;
- release layer where applicable;
- explicit provenance and donor mapping.

### Living package

Use when a surface remains active and evolves through traceable deltas.

Should contain:

- living index;
- donor relation map;
- role-based packaging boundaries;
- no false claim that one snapshot exhausts the system.

## What must not happen

- no blind archive dumping;
- no mixing theory, archive, governance, and release residue without role notes;
- no fake completeness claims;
- no packaging that hides provenance;
- no packaging that strips safety, detox, or operator-control rules.
